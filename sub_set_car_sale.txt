# Foundation Models — Overview

Large pretrained models that transfer to many downstream tasks with minimal fine-tuning. Organized by modality and use case.

---

## Vision Foundation Models

| Model | By | Key strength | Use case |
|-------|-----|-------------|----------|
| [[DiNOv2]] | Meta | Dense features, anomaly detection | Defect detection, classification |
| [[DiNOv3]] | Meta | 7B params, Gram anchoring, beats weakly-supervised | Drop-in DINOv2 upgrade, better patch features |
| [[SAM2]] | Meta | Pixel-level segmentation from a click | Defect localization, masking |
| [[CLIP]] | OpenAI | Image + text jointly | Image search by description |
| [[SigLIP]] | Google | Improved image-text matching | Classification with text labels |
| [[DepthAnything]] | HuggingFace/ByteDance | Monocular depth estimation | 3D inspection, surface profiling |

## Anomaly Detection Methods (vision)

| Method | Strength | Notes |
|--------|---------|-------|
| [[PatchCore]] | State of the art on MVTec | DINOv2 patch features + memory bank |
| [[EfficientAD]] | Fast, production-ready | Purpose-built for edge deployment |

---

## How they relate to your stack

```
Visual QC (images)
    → DINOv2       — feature extraction, anomaly detection (Phase 1, 4)
    → SAM2         — pixel-level masks if localization needed
    → PatchCore    — patch-level anomaly detection (Phase 4)
    → EfficientAD  — when PatchCore is too slow for Thor

Text-guided search
    → CLIP / SigLIP — find defect images by description

3D / depth
    → DepthAnything — surface profiling, height map estimation

Time series (process signals)
    → MINIROCKET   — not a foundation model, but the right tool for sensor data
```
